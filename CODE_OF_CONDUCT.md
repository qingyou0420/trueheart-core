# Code of conduct

## Provenance

This is an original project policy written for TrueHeart Core and covered by
the repository's MIT license. It does not copy or adopt the Contributor
Covenant or another externally licensed code-of-conduct text.

## Our standard

We want participation in TrueHeart Core to be respectful, constructive, and
safe. Be considerate, welcome differing experience levels, critique ideas
rather than people, respect privacy, and accept responsibility for mistakes.

Harassment, threats, discrimination, sexualized attention, deliberate
intimidation, doxxing, and publication of another person's private information
are not acceptable. Do not use project spaces to collect or expose sensitive
prompts, conversations, credentials, databases, or logs.

## Scope and enforcement

This standard applies in project repositories, issue trackers, reviews,
discussions, and public spaces where someone represents the project.
Maintainers may edit or remove inappropriate contributions and may temporarily
or permanently restrict participation when necessary.

Before public launch, maintainers will enable GitHub private vulnerability
reporting. Publication is blocked until private vulnerability reporting is enabled.
Once enabled, open the repository's **Security** tab, choose **Advisories**, and
select **Report a vulnerability**. Prefix the report title with `[Conduct]`.
This deliberately reuses a project-controlled private inbox for sensitive
conduct reports; it does not mean a conduct report is a software vulnerability.

This local checkout does not claim that private reporting is enabled now. If
the route is unavailable, do not submit sensitive details publicly.
GitHub Report abuse remains available for conduct that violates GitHub platform
policies.
Security vulnerabilities follow [SECURITY.md](SECURITY.md). No response SLA is
promised.

Enforcement decisions should be proportionate, documented privately where
appropriate, and protect the privacy and safety of affected people.
